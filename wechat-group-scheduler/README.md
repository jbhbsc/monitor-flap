# 微信定时群聊助手

Windows 个人微信的本地文字发送项目。Node.js 提供中文配置页面和排程，Windows PowerShell / Win32 负责窗口操作，不使用微信非官方协议。无第三方 npm 运行依赖；前端回归测试使用开发依赖 linkedom。

## Vercel 在线预览

已发布：**https://wechat05.vercel.app**。`wechat.vercel.app` 已被占用，使用这个较短的替代地址。

项目提供 `vercel.json`，以 `public` 为静态输出目录，无需构建或安装依赖。在线页面仅展示原操作界面，并提供 `http://127.0.0.1:8787/` 本机入口；所有配置、截图、模拟和真实发送在在线预览中禁用，不请求本机或云端 API。

Vercel 不能运行本项目的 Windows PowerShell、桌面微信和持续排程。实际发送请在 Windows 电脑双击 `start.cmd`，然后打开本机页面。上线不代表微信可以在云端发送。`.vercelignore` 仅允许上传网页、部署配置与包元信息，排除本机群配置、消息、截图、日志、运行记录和 Windows 程序。

重新部署命令：`npx vercel deploy --cwd "D:\vs-code\wechat-group-scheduler" --project wechat --scope jh-s-projects12 --prod`。短域名需要在当前 Vercel 帐号下可用，不能占用他人已有的 `*.vercel.app` 地址。

## 默认时间

- 时区：北京时间 `Asia/Shanghai`，不依赖电脑时区。
- 每天 **07:00 到 20:00，含 20:00，共 14 轮**。
- 所有群使用同一份文字；按配置顺序，每 **60 秒**处理一个群。
- 10 个群时：第一轮 `07:00、07:01…07:09`；最后一轮 `20:00…20:09`；每日计划 140 条。
- 运行中首次执行稍有延迟时，后续仍至少保持配置的群间隔（默认 60 秒）；每个时间点允许迟到 45 秒。超过则跳过，不集中补发。
- 重启服务后默认为**停止状态**。已经预留或尝试的真实任务当天同轮不自动重发；模拟记录与真实记录分开。

## 按时 / 按分与分钟设置

开始和结束都可以选择 **时:分**，轮次单位可选：

- **按时 · 每小时一轮**：如 `07:35–09:40`，会在 `07:35、08:35、09:35` 启动，共 3 轮。
- **按分 · 每分钟一轮**：如 `07:35–07:38`，会在 `07:35、07:36、07:37、07:38` 启动，共 4 轮，适合测试。

结束时间是**轮次启动上限**，轮内最后几个群可以在结束时间之后发送，但不能跨到次日。群间隔可以设为 **1–1800 秒**，默认依然是 60 秒。每分钟模式要求 `(群数 - 1) × 群间隔 < 60 秒`，避免计划上的轮次重叠。例如 10 个群可以设置 5 秒间隔；从按时切换到按分时，页面会在必要时自动缩短间隔并提示，保存前仍可修改。

微信实际搜索、校验、发送每条消息需要数秒，即使设为 1 秒也不会并行操作。实际吞吐不足时，过期的定时任务会跳过；若只想逐个验证发送，请使用下面的手动发送，不必把一天都设成每分钟模式。

## 手动发送与手动模拟

“运行与预览”区域新增手动发送：选择 **全部群（发送一轮）** 或 **单个群**。

- **手动模拟一轮**：立即启动，按配置的群间隔记录一次执行，不操作微信，不要求完成绑定。
- **手动发送**：先核对弹窗里的目标群和文案，确认后启动一轮真实发送。所选目标必须完成绑定。

手动任务不受每日开始/结束时间限制，完成一轮后自动停止，不开启每日循环。第一条通常在下一秒调度时处理；如果刚执行过真实发送，会等待配置的最小间隔。后续群因执行较慢而延迟时会继续处理，不按定时任务的 45 秒规则跳过。异常仍会立即停止。

手动与定时任务互斥；请先点“停止任务”，再使用另一种方式。手动记录独立于每日排程，**不会抵扣定时的一轮**。同一手动请求重复提交不会再次发送；再次主动点击并确认是一次新的发送。停止或中断后，先核查微信中的实际结果。

手动一轮会显示已执行群数、当前群、下一群和剩余等待时间，以及失败时的群名。群间隔为 60 秒时，第一个群处理完仍需等待下一群时间；等待期间保持微信在前台，避免操作键盘鼠标。完成或停止后发送按钮会恢复，可以重新选择单群发送；每次手动操作只执行一轮，持续循环使用“启动真实发送”。

未绑定的目标会在手动按钮旁显示提示，点击“前往校准与绑定”可跳到首次校准区域并自动选择待绑定群。点击后的检查进度、配置错误和发送失败原因都会显示在操作附近；确认窗口中的错误会显示在窗口内，不需要返回页顶查找。

已有配置会自动补上 `startMinute: 0`、`endMinute: 0` 和 `roundUnit: "hour"`，保留原有群名单、文案、图像绑定和整点防重复记录。

## 启动

需要 Windows 10/11、Node.js 22 或更新版本、已登录的电脑版微信。保持桌面解锁、电脑不休眠。微信和本程序应使用同一普通用户权限，不要将其中一个单独以管理员身份运行。

双击 **`start.cmd`**，或在本项目目录执行：

```powershell
npm start
```

浏览器打开 **http://127.0.0.1:8787**。不需要 `npm install`。如果双击后浏览器先于服务打开，稍等并刷新即可。关闭终端会停止项目；页面关闭不会停止终端中的任务。

首次启动请先填写实际群名（每行一个）和文案，保存后检查时间表。项目没有预填真实联系人或文案，也不会自行开启真实发送。

## 首次绑定：让脚本能辨认群聊

目前微信版本之间的可访问性控件差异较大，本项目使用**严格的图像指纹比对**。它不使用 OCR 猜测群名。第一次需要手动绑定，微信界面变化后可能需要重新绑定。

1. 在微信中打开第一个目标群，核对确实是群聊，清空输入框，点击一处无功能的空白区域让输入框失焦。窗口不要被其他窗口、通知或工具条遮挡。
2. 在本地页面选择对应群名，点击“获取微信截图”。该操作会把微信带到前台；截图后手动返回配置页面。
3. 在截图上完成五步校准：框选完整群标题、框选空白文字输入区域、点击无功能空白处、点击输入位置、点击发送按钮中心。
4. **标题框应紧贴完整群名，建议包含群人数；不要框入消息、时钟或动态状态。** 输入框要覆盖整个文字编辑区域，排除工具栏与发送按钮。空白失焦点不能是群名、聊天记录、链接或按钮，也不能位于以上两个框内。
5. 核对截图中的群与下拉框选择一致，确认输入框为空，勾选确认后保存绑定。
6. 手动打开下一群，清空输入并点击相同空白位置；回到页面选择下一群，再重新截图和保存。相同窗口尺寸下可复用五步布局。
7. 所有群绑定完成后，先运行模拟模式核对排程。停止模拟，再核对真实发送弹窗中的群名单和文案，点击启动。

绑定区支持 **重置当前群绑定** 和 **重置全部绑定**。选择当前群后，重置当前群只清除它的绑定，保留其他群及共享布局；重置全部会清除所有绑定（包括以前移出名单的群）及校准布局。操作前会显示范围确认，运行中需先停止任务。重置完成会清除页面当前截图和勾选状态，需重新获取截图。群名单、文案、时间、日志和防重复发送记录会保留，重置绑定不会让已发送的计划自动重发。

必须使用可区分的群名。不同群标题截图完全相同时会拒绝绑定。标题图像只能证明“当前会话标题与人工绑定时一致”，不是微信内部的不可变群 ID；如果删除群后又创建同名群、同名联系人和群的标题显示相同，应重新检查绑定。建议给目标群设置不与联系人或其他群重名的名称。

微信搜索快捷键使用 **Ctrl+F**，粘贴完整群名后按 Enter 打开默认结果，再检查标题。若你的微信 Ctrl+F 行为不同、结果无法唯一定位、标题未匹配，项目会停止，需要适配该版本后再用。不要为了通过校验而把标题框缩小为空白区域。

## 实际发送流程与结果含义

每次操作会依次：确认唯一微信主窗口和解锁桌面 → 搜索群 → 点击校准的空白位置失焦 → 严格比对窗口尺寸和完整标题，检查输入区域为空白 → 粘贴文字 → 复制编辑内容检查是否与配置完全一致 → 再次比对标题 → 点击发送按钮 → 检查输入框恢复为空白。

新版空白检查允许第一行起始位置的一根细文字光标闪烁和轻微背景色误差，其他文字、标点或异常内容仍会拦截；粘贴后还会逐字核对编辑内容。绑定时就会检查输入区域是否为空。旧绑定仍使用原图像指纹；如提示受光标影响，请清空输入框、重新获取截图并保存该群绑定，不必重置其他群。蓝框应覆盖文字编辑区内部，避开工具栏、发送按钮和边框。

微信的“长按鼠标 语音输入”是鼠标悬停提示。获取截图和发送校验前，程序会把鼠标移到微信窗口左上角边缘（只移动，不点击），等待 900 毫秒让提示消失。点击输入框后也会移开鼠标，保留文字焦点。自动操作期间不要移动鼠标。已经截进提示的旧图不会因点击“保存”而改变，需要重新获取截图；若移开鼠标后提示仍不消失，程序会继续停止并显示原因，需检查该微信版本的提示行为。

发生异常会停止整项任务。群成员数变化、群名变化、主题变化、DPI/显示器变化、窗口尺寸变化、鼠标悬停效果或遮挡，都可能使严格比对失败。先手动核查微信，再恢复界面或重新绑定。它优先停止，不能保证适配所有微信版本。

日志中的“已执行发送，送达未核验”只表示点击发送后输入框清空，**不能证明微信服务器已接收、对方已收到或已读**。网络错误、风险限制可能仍出现在聊天窗口中，请以微信实际状态为准。

进程在 UI 操作前写入持久记录。失败、被停止、超时或崩溃时，结果可能未知，因此同一真实任务不会自动重试。不要直接删除 `state.json` 来重试，否则可能重复发送。停止会中断正在进行的窗口操作，可能在微信留下草稿；请人工检查。

运行会移动鼠标、切换窗口、使用剪贴板（原剪贴板内容不保留）。发送期间不要同时操作电脑；建议使用专用 Windows 登录会话。最小化后会尝试恢复微信；锁屏和休眠时不能执行。**不支持后台无界面发送**。

### 没有操作电脑却提示微信未处于前台

从浏览器启动的 PowerShell 可能被 Windows 拒绝切换前台，或微信恢复窗口需要更长时间，因此该提示并不等于用户移动了鼠标。开始截图或单群发送时，程序现在最多进行 8 次激活尝试，每次等待 200 毫秒，并在必要时短暂连接前台线程输入队列后立即解除；不会通过点击其他应用或模拟 Alt 键抢焦点。

仍失败会显示“启动失败：Windows 未允许程序将微信切到前台”，此时本次群操作尚未搜索、输入消息或点击发送。先确认桌面已解锁、微信主窗口正常打开，且微信和 Node 服务使用相同权限，再用“获取微信截图”验证切换。无需重置已有绑定。操作已经开始后若微信失去前台，仍会立即停止，不会继续抢焦点并盲目输入。

## 本地文件

- `data/config.json`：群名、统一文案、时间和布局。
- `data/bindings/*.json`：群标题和输入区域的图像指纹、空白区域背景特征、布局指纹；不存完整截图。
- `data/state.json`：防重复执行记录，损坏时拒绝启动。
- `data/events.jsonl`：事件日志，包含群名，不主动记录消息正文。页面仅显示本次进程最近日志。
- `data/server.lock`：单实例锁；崩溃后会在确认原进程不存在时自动恢复。

数据仅保存在本机，已加入 `.gitignore`。截图只通过本机页面传输、在服务内存临时保存（最多 5 张，最长 10 分钟可绑定），不上传外部服务。服务只监听 `127.0.0.1`，校验 Host、Origin 和每次启动生成的防跨站令牌。

自定义端口：在 PowerShell 中设置 `$env:WECHAT_PORT = '8788'` 后运行 `npm start`，访问对应地址。测试可用 `WECHAT_DATA_DIR` 指向独立数据目录。

## 验证与兼容范围

```powershell
npm ci
npm test
npm run check
```

测试覆盖小时/分钟排程边界、旧配置兼容、北京时间、错过时段、真实间隔、手动单群/一轮、手动请求去重、模式互斥、持久预留、崩溃去重、异常停止、并发执行、配置校验与本地 HTTP 接口。测试和模拟模式均不会操作微信或发送消息。

真实微信操作需要在你的电脑上完成校准并用实际群聊验证。项目生成时没有配置你的群名或文案，没有执行真实发送。个人微信没有面向此用途的官方发送接口；本项目不能保证微信版本兼容或账号不受限制。微信群规则允许的通知场景更适合此类工具。

```text

src/store.mjs       本地持久化和单实例锁
src/bridge.mjs      Windows 子进程通信
src/server.mjs      仅本机 HTTP 服务
windows/bridge.ps1  微信窗口操作、截图、图像比对

```
